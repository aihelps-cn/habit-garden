# 小小成长家 v3 · 服务器部署与安卓安装手册

适用域名：**https://hz.aihelps.cn**  
结构：安卓 / iOS / 浏览器 → HTTPS → Nginx → Node.js API → MySQL 8.0。

孩子和家长的账号、绑定关系、任务、打卡、积分及兑换记录统一存放在服务器。手机只保存登录凭据和应用界面。同一账号换设备登录后，读取的是服务器上同一份数据。

本次已经确认该域名的 `/api/health` 可访问，MySQL 健康检查正常。线上返回的是旧版健康接口，**先更新服务器，再使用本次安卓安装包**。本文提供部署步骤；本次没有登录服务器执行更新。

## 1. 本次交付内容

| 文件 / 目录 | 作用 |
| --- | --- |
| `habit-garden-server-v3.zip` | 服务器部署包，不含真实 `.env`、数据库数据或安卓签名密钥 |
| `habit-garden-source-v3.zip` | 完整源码：服务端、共享界面、iOS 与安卓工程、测试和手册 |
| `habit-garden-3.0.0-release.apk` | 已配置本域名的安卓安装包 |
| `backend/` | Node.js API、权限、登录和 MySQL 结构 |
| `frontend/` | 共用界面源码；Docker 构建时直接复制进服务端镜像 |
| `mobile/ios/`、`mobile/android/` | iOS、安卓原生工程 |
| `mobile/signing/` | 本机的安卓签名资料；另行保密备份，不在源码包内 |

服务器只需要部署服务器包。不要将整个目录放到 Nginx 的公开静态目录，也不要把 `.env`、备份或签名文件作为网站资源提供下载。

## 2. 已有服务器：保留数据更新

你已经有正在运行的网站，优先按本节操作。

### 2.1 找到原来的部署目录

登录服务器，进入原本保存 `compose.yaml` 和 `.env` 的目录。例如：

```sh
cd /opt/habit-garden
docker compose ps
```

这里的路径只是示例；应替换成当前真实目录。确认显示的是现有的 `app` 和 `mysql`。不要另外创建一个全新的部署目录后误以为原数据消失了，也不要改 Compose 中的项目名 `habit-garden` 或现有数据卷。

### 2.2 先备份

在原目录执行：

```sh
mkdir -p backups
chmod 700 backups
cp .env backups/env-before-v3
chmod 600 backups/env-before-v3
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" exec mysqldump --single-transaction --no-tablespaces --set-gtid-purged=OFF -u habit habit_garden' > backups/before-v3.sql
chmod 600 backups/before-v3.sql
test -s backups/before-v3.sql
```

确认最后一条命令成功，备份文件非空。下载一份到安全位置保存；数据库备份包含账号资料和业务数据。

### 2.3 上传并解压更新包

将 `habit-garden-server-v3.zip` 上传到原部署目录，并在该目录执行：

```sh
unzip -o habit-garden-server-v3.zip
```

压缩包根目录就是 `compose.yaml` 等文件，不再套一层文件夹；其中不包含 `.env`，不会覆盖原来的数据库密码。旧版目录中原有的其他文件不会影响本版本构建。

打开现有 `.env`，核对以下设置：

```dotenv
PUBLIC_ORIGIN=https://hz.aihelps.cn
APP_PORT=8080
BIND_ADDRESS=127.0.0.1
COOKIE_SECURE=true
TRUST_PROXY=1
```

保留现有的 `MYSQL_PASSWORD` 和 `MYSQL_ROOT_PASSWORD`，不要用示例密码替换。以上代理设置适用于同机 Nginx 是应用唯一可信入口的情况；其他代理结构需按实际调整。

### 2.4 重建应用

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 app
curl -fsS https://hz.aihelps.cn/api/health
```

新版健康接口应包含：

```json
{"ok":true,"database":"mysql","timezone":"Asia/Shanghai","version":"3.0.0","persistent_sessions":true,"native_auth":true}
```

更新期间会短暂重启应用，数据库数据卷保留。应用首次启动会把 `sessions.expires_at` 改成可空字段；新会话没有固定有效期，仍有效的旧会话在下次使用时升级。已经过期的旧登录需要重新登录一次，不会被自动恢复。

**不要执行 `docker compose down -v`，它会删除 MySQL 数据卷。**

## 3. 如果需要从零部署

推荐使用一台 Linux 服务器，安装 Docker Engine、Docker Compose v2、Nginx，并准备已解析到服务器的域名和有效 HTTPS 证书。Docker 的安装命令因操作系统而异，使用 [Docker 官方安装说明](https://docs.docker.com/engine/install/) 对应的发行版步骤。

首次部署：

```sh
mkdir -p /opt/habit-garden
cd /opt/habit-garden
unzip /上传路径/habit-garden-server-v3.zip
cp .env.example .env
chmod 600 .env
```

用编辑器修改 `.env`：

```dotenv
PUBLIC_ORIGIN=https://hz.aihelps.cn
MYSQL_PASSWORD=填写新的独立长随机密码
MYSQL_ROOT_PASSWORD=填写另一个独立长随机密码
APP_PORT=8080
BIND_ADDRESS=127.0.0.1
COOKIE_SECURE=true
TRUST_PROXY=1
```

可分别执行两次以下命令生成密码，将结果填入对应位置：

```sh
openssl rand -hex 24
```

然后启动：

```sh
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:8080/api/health
```

首次拉取镜像和初始化 MySQL 需要等待。`mysql` 健康后 `app` 才会启动。不要把 3306 暴露到公网；本项目默认只将应用端口暴露给服务器本机。

## 4. Nginx 与 HTTPS

你目前的域名已能正常通过 HTTPS 访问。如果现有反向代理工作正常，保留原证书和站点配置，只核对它代理到 `127.0.0.1:8080`。

现有 HTTPS 的 `server` 块中应包含：

```nginx
server_name hz.aihelps.cn;

location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

证书路径、`listen 443 ssl` 等设置沿用你的 Nginx / 宝塔 / 1Panel 配置。**不要把上面这个片段当作完整的 HTTPS 配置覆盖现有文件。**

如果使用宝塔或 1Panel：选择 `hz.aihelps.cn` 网站，保留 SSL 证书，配置反向代理目标为 `http://127.0.0.1:8080`，启用 HTTP 跳转 HTTPS。不要把 Node.js 源码目录设置成可公开浏览的静态站点。

使用系统 Nginx 管理时，修改后先验证再重载：

```sh
sudo nginx -t
sudo systemctl reload nginx
```

手机 App 必须通过有效 HTTPS 证书访问；不支持明文 HTTP、自签名证书或跳过证书校验。

## 5. 安装安卓 App

1. 先完成第 2 节服务器更新，并检查健康接口出现 `native_auth: true`。
2. 把 `habit-garden-3.0.0-release.apk` 传到安卓手机。
3. 在文件管理器打开 APK；如果系统提示，允许该文件管理器“安装未知应用”，然后安装。
4. 打开「小小成长家」，使用现有账号登录；无需重新注册同名账号。
5. 关闭并重新打开 App，应直接进入原账号。

最低支持 Android 7.0。APK 已配置 `https://hz.aihelps.cn`，孩子不需要手动填写服务器地址。

这是直接安装的 APK，不是应用商店下载。系统安全扫描提示按设备提示处理，不需要关闭整机安全防护。如果之前安装过不同签名的开发测试版，可能无法覆盖；确认服务器数据已保存后可卸载旧测试版再安装。以后使用同一签名密钥且提高版本号的正式包，可以正常覆盖升级。

## 6. 家长和孩子的首次使用

1. 家长注册家长账号，孩子注册孩子账号；已有账号直接登录。
2. 在孩子端「我的家庭」生成绑定码。
3. 家长在「我的家庭」输入孩子的绑定码。
4. 家长添加任务、积分和奖励。
5. 孩子记录完成并提交审核；家长通过后加分。
6. 孩子用积分兑换奖励，家长兑现后确认。

手机端、网页端的数据一致。联网使用时会自动刷新，也可重新打开应用读取最新内容。日常无需退出登录；孩子直接关闭 App 即可。为避免误触，退出需要二次确认。

长期登录仍有明确的退出方式：主动退出会撤销该设备凭据；修改密码会使其他设备重新登录。安卓清除应用数据、卸载或系统安全存储被清除后，需要再登录。网页受浏览器 Cookie 规则限制，长期不使用或清理浏览器数据后也可能需要重新登录。

## 7. 日常维护与备份

查看状态、日志：

```sh
docker compose ps
docker compose logs --tail=100 app
docker compose logs --tail=100 mysql
```

应用重启：

```sh
docker compose restart app
```

定期生成数据库备份，使用第 2.2 节的 `mysqldump` 命令，并为每份备份使用不同日期的文件名。保留服务器以外的副本。容器重建不会清空数据，服务器磁盘损坏或误删数据卷仍需要备份恢复。

恢复数据库时，在维护窗口先备份当前数据，然后：

```sh
docker compose stop app
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" exec mysql -u habit habit_garden' < backups/要恢复的备份.sql
docker compose start app
```

不要让用户在恢复期间继续写入。修改 `.env` 的数据库密码不会自动修改已有 MySQL 用户密码；轮换密码时要先在数据库中同步修改。

## 8. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 网站 502 | 查看 `docker compose ps` 和 `app` 日志，确认代理端口与 `APP_PORT` 一致 |
| 数据库连接失败 | 核对现有 `.env` 和 MySQL 内的密码是否一致；不要删除数据卷重来 |
| 提示“来源不允许” | `PUBLIC_ORIGIN` 必须为 `https://hz.aihelps.cn`，不带 `/api` |
| App 提示“服务器未返回手机端登录凭据” | 服务器仍是旧版；重新部署并核对健康接口版本 |
| App 显示连接失败 | 检查手机网络、HTTPS 证书、域名解析和健康接口；点“重新连接” |
| 登录后立即失效 | 检查是否刚改密码；网页端还要确认 HTTPS 与 `COOKIE_SECURE=true` |
| 更新后界面没变 | Docker 镜像需重建；App 界面修改后需重新构建 APK 并安装 |
| 手机显示安装包冲突 | 检查旧版签名、包名和版本号；后续更新必须用原签名密钥 |
| 23:30 后没有立即自动通过 | 正常检查间隔 30 秒；查看服务日志和打卡是否已提交，晚提交截止次日 |

## 9. 安卓后续版本和 iOS

完整源码包中 `mobile/README.md` 有构建步骤。安卓发布密钥位于本机 `mobile/signing/`，应加密备份整个目录，并妥善保存；不要上传到网站或公开仓库。遗失密钥会影响后续覆盖更新。

iOS 工程已提供，但需要完整 Xcode 和你自己的 Apple 签名配置才能编译、安装或分发。安卓 APK 不能直接安装到 iPhone。

当前自动验证覆盖服务端会话逻辑、前端交互与手机端 JS 打包。真实 MySQL 迁移验收、手机系统凭据存储以及完整业务流程，仍应在部署后按第 5、6 节实际验证。
