# 小小成长家 v3 · 服务器部署与安卓安装手册

适用域名：**https://hz.aihelps.cn**  
结构：安卓 / iOS / 浏览器 → HTTPS → Nginx → Node.js API → MySQL 8.0。

孩子和家长的账号、绑定关系、任务、打卡、积分及兑换记录统一存放在服务器。手机只保存登录凭据和应用界面。同一账号换设备登录后，读取的是服务器上同一份数据。

**最新部署验证（2026-10-20）：** v3.0.0 已成功部署到 `124.222.165.127:/root/hz/`，健康接口返回完整 v3 格式（`version: "3.0.0"`, `native_auth: true`），MySQL 数据卷保留。本手册同时保留"保留数据升级"和"从零部署"两条路径，供后续版本更新时参考。

## 1. 源码结构（不是 zip 交付）

本项目以源码目录直接部署，不需要预先打包 zip。从源码仓库 clone 下来后，关键文件如下：

| 文件 / 目录 | 作用 |
| --- | --- |
| `compose.yaml` | Docker Compose 编排（Node 应用 + MySQL 8.0） |
| `Dockerfile` | 生产镜像构建：Node 22 slim，直接 `COPY frontend ./dist` |
| `.env.example` | 环境变量模板（复制为 `.env` 后修改） |
| `backend/` | Node.js API、权限、登录和 MySQL 结构 |
| `frontend/` | 共用界面源码；Docker 构建时直接复制进服务端镜像的 `dist/` |
| `server.mjs` | HTTP 服务入口和自动审核定时任务 |
| `mobile/ios/`、`mobile/android/` | iOS、安卓原生工程 |
| `mobile/signing/` | 本机的安卓签名资料；另行保密备份，不在源码仓库 |
| `deploy/nginx.conf.example` | Nginx 反向代理参考配置 |

服务器上只需要 Docker + Docker Compose + Nginx。不要将源码目录放到 Nginx 的公开静态目录，也不要把 `.env`、备份或签名文件作为网站资源提供下载。

## 2. 已有服务器：保留数据更新

你已经有正在运行的网站，优先按本节操作。

### 2.1 定位旧版部署目录

首次登录服务器时，旧版可能部署在任意路径。用以下命令找到它：

```sh
# 查 compose.yaml 位置（排除 node_modules 和 .git）
find / -name compose.yaml -not -path "*/node_modules/*" -not -path "*/.git/*" 2>/dev/null

# 也可以查正在跑的容器反推：
docker compose ps       # 在各候选目录下分别执行
docker ps               # 看容器名里的项目标识
```

确认后进入那个目录，例如本次实际部署目录是 `/root/hz/`：

```sh
cd /root/hz
docker compose ps
```

不要另外创建一个全新的部署目录后误以为原数据消失了，也不要改 Compose 中的项目名 `habit-garden` 或现有数据卷。

### 2.2 先备份

在原目录执行：

```sh
mkdir -p backups
chmod 700 backups
cp .env backups/env-before-v3
chmod 600 backups/env-before-v3
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" exec mysqldump --single-transaction --no-tablespaces --set-gtid-purged=OFF -u habit habit_garden' > backups/before-v3.sql
chmod 600 backups/before-v3.sql
test -s backups/before-v3.sql
```

确认最后一条命令成功，备份文件非空。下载一份到安全位置保存；数据库备份包含账号资料和业务数据。

### 2.3 上传新版代码

推荐使用 `rsync` 从本地同步到服务器（避免 zip 解压覆盖 `.env`）。在本地项目根目录执行：

```sh
# 替换 USER@HOST 和目标路径
rsync -avz \
  --exclude='.env' \
  --exclude='backups/' \
  --exclude='.git/' \
  --exclude='node_modules/' \
  --exclude='mobile/' \
  --exclude='deploy/' \
  --exclude='.gitignore' \
  --exclude='.dockerignore' \
  /path/to/habit-garden/ USER@HOST:/root/hz/
```

或者如果你已用 scp 上传了 zip 文件，解压时务必用 `-o` 覆盖但不碰 `.env`：

```sh
# 服务器端
unzip -o habit-garden-source.zip -d /root/hz/
```

两种方式都不会覆盖原有的 `.env`。上传完成后在服务器上核对 `.env`：

```sh
cd /root/hz
# 只看变量名，不泄露密码
while IFS= read -r line; do
  if echo "$line" | grep -qE '^[A-Z_]+='; then
    key=$(echo "$line" | cut -d= -f1)
    val=$(echo "$line" | cut -d= -f2-)
    echo "$key=<${#val} chars>"
  fi
done < .env
```

必须能看到 `PUBLIC_ORIGIN`、`MYSQL_PASSWORD`、`MYSQL_ROOT_PASSWORD` 都有值。如果之前的 `.env` 缺少 `APP_PORT`、`BIND_ADDRESS`、`COOKIE_SECURE`、`TRUST_PROXY` 这些 v3 新增变量，手动补上（参考 `.env.example`）。

### 2.4 重建应用

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 app
curl -fsS https://hz.aihelps.cn/api/health | python3 -m json.tool
```

新版健康接口应包含：

```json
{
    "ok": true,
    "database": "mysql",
    "timezone": "Asia/Shanghai",
    "version": "3.0.0",
    "persistent_sessions": true,
    "native_auth": true
}
```

其中 `native_auth: true` 是 v3 的标志性字段。如果看到旧版格式（只有 ok/database/timezone），说明服务器还没重启或 Nginx 代理了旧容器。

更新期间会短暂重启应用，**MySQL 数据卷保留**。应用首次启动会把 `sessions.expires_at` 改成可空字段；新会话没有固定有效期，仍有效的旧会话在下次使用时升级。已经过期的旧登录需要重新登录一次，不会被自动恢复。

**绝对不要执行 `docker compose down -v`，它会删除 MySQL 数据卷。**

## 3. 如果需要从零部署

推荐使用一台 Linux 服务器，安装 Docker Engine、Docker Compose v2、Nginx，并准备已解析到服务器的域名和有效 HTTPS 证书。Docker 的安装命令因操作系统而异，使用 [Docker 官方安装说明](https://docs.docker.com/engine/install/) 对应的发行版步骤。

首次部署：

```sh
# 在服务器上
mkdir -p /opt/habit-garden
cd /opt/habit-garden

# 从本地 rsync 上传（排除 .env 和备份）
# 在本地执行：rsync -avz --exclude='.env' --exclude='backups/' --exclude='mobile/' \
#   /path/to/habit-garden/ USER@HOST:/opt/habit-garden/

cp .env.example .env
chmod 600 .env
```

用编辑器修改 `.env`：

```dotenv
PUBLIC_ORIGIN=https://hz.aihelps.cn
MYSQL_PASSWORD=填写新的独立长随机密码
MYSQL_ROOT_PASSWORD=填写另一个独立长随机密码
APP_PORT=8080
BIND_ADDRESS=127.0.0.1
COOKIE_SECURE=true
TRUST_PROXY=1
```

可分别执行两次以下命令生成密码，将结果填入对应位置：

```sh
openssl rand -hex 24
```

然后启动：

```sh
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:8080/api/health | python3 -m json.tool
```

首次拉取镜像和初始化 MySQL 需要等待。`mysql` 健康后 `app` 才会启动。不要把 3306 暴露到公网；本项目默认只将应用端口暴露给服务器本机。

## 4. Nginx 与 HTTPS

你目前的域名已能正常通过 HTTPS 访问。如果现有反向代理工作正常，保留原证书和站点配置，只核对它代理到 `127.0.0.1:8080`。

**实际验证（2026-10-20）：** 服务器 Nginx 配置位于 `/etc/nginx/conf.d/hz.aihelps.cn.conf`，由 Certbot 管理 HTTPS 证书，HTTP 自动 301 跳转 HTTPS。代理已正常工作到 `127.0.0.1:8080`。

现有 HTTPS 的 `server` 块中应包含以下关键指令（完整参考见 `deploy/nginx.conf.example`）：

```nginx
server_name hz.aihelps.cn;

location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

⚠️ **注意 `X-Forwarded-Proto`**：服务器上如果缺少这一行，且 `.env` 设了 `TRUST_PROXY=1`，Node 应用的安全 Cookie 判断会出错。当前服务器上 Certbot 管理的配置文件里没有这行，建议补上。

证书路径、`listen 443 ssl` 等设置沿用你的 Nginx / 宝塔 / 1Panel 配置。**不要把上面这个片段当作完整的 HTTPS 配置覆盖现有文件。**

如果使用宝塔或 1Panel：选择 `hz.aihelps.cn` 网站，保留 SSL 证书，配置反向代理目标为 `http://127.0.0.1:8080`，启用 HTTP 跳转 HTTPS。不要把 Node.js 源码目录设置成可公开浏览的静态站点。

使用系统 Nginx 管理时，修改后先验证再重载：

```sh
sudo nginx -t
sudo systemctl reload nginx
```

手机 App 必须通过有效 HTTPS 证书访问；不支持明文 HTTP、自签名证书或跳过证书校验。

## 5. 安装安卓 App

1. 先完成第 2 节服务器更新，并检查健康接口出现 `native_auth: true`。
2. 把 `habit-garden-3.0.0-release.apk` 传到安卓手机。
3. 在文件管理器打开 APK；如果系统提示，允许该文件管理器“安装未知应用”，然后安装。
4. 打开「小小成长家」，使用现有账号登录；无需重新注册同名账号。
5. 关闭并重新打开 App，应直接进入原账号。

最低支持 Android 7.0。APK 已配置 `https://hz.aihelps.cn`，孩子不需要手动填写服务器地址。

这是直接安装的 APK，不是应用商店下载。系统安全扫描提示按设备提示处理，不需要关闭整机安全防护。如果之前安装过不同签名的开发测试版，可能无法覆盖；确认服务器数据已保存后可卸载旧测试版再安装。以后使用同一签名密钥且提高版本号的正式包，可以正常覆盖升级。

## 6. 家长和孩子的首次使用

1. 家长注册家长账号，孩子注册孩子账号；已有账号直接登录。
2. 在孩子端「我的家庭」生成绑定码。
3. 家长在「我的家庭」输入孩子的绑定码。
4. 家长添加任务、积分和奖励。
5. 孩子记录完成并提交审核；家长通过后加分。
6. 孩子用积分兑换奖励，家长兑现后确认。

手机端、网页端的数据一致。联网使用时会自动刷新，也可重新打开应用读取最新内容。日常无需退出登录；孩子直接关闭 App 即可。为避免误触，退出需要二次确认。

长期登录仍有明确的退出方式：主动退出会撤销该设备凭据；修改密码会使其他设备重新登录。安卓清除应用数据、卸载或系统安全存储被清除后，需要再登录。网页受浏览器 Cookie 规则限制，长期不使用或清理浏览器数据后也可能需要重新登录。

## 7. 日常维护与备份

查看状态、日志：

```sh
docker compose ps
docker compose logs --tail=100 app
docker compose logs --tail=100 mysql
```

应用重启：

```sh
docker compose restart app
```

定期生成数据库备份，使用第 2.2 节的 `mysqldump` 命令，并为每份备份使用不同日期的文件名。保留服务器以外的副本。容器重建不会清空数据，服务器磁盘损坏或误删数据卷仍需要备份恢复。

恢复数据库时，在维护窗口先备份当前数据，然后：

```sh
docker compose stop app
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" exec mysql -u habit habit_garden' < backups/要恢复的备份.sql
docker compose start app
```

不要让用户在恢复期间继续写入。修改 `.env` 的数据库密码不会自动修改已有 MySQL 用户密码；轮换密码时要先在数据库中同步修改。

## 8. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 网站 502 | 查看 `docker compose ps` 和 `app` 日志，确认代理端口与 `APP_PORT` 一致 |
| 数据库连接失败 | 核对现有 `.env` 和 MySQL 内的密码是否一致；不要删除数据卷重来 |
| 提示“来源不允许” | `PUBLIC_ORIGIN` 必须为 `https://hz.aihelps.cn`，不带 `/api` |
| App 提示“服务器未返回手机端登录凭据” | 服务器仍是旧版；重新部署并核对健康接口版本 |
| App 显示连接失败 | 检查手机网络、HTTPS 证书、域名解析和健康接口；点“重新连接” |
| 登录后立即失效 | 检查是否刚改密码；网页端还要确认 HTTPS 与 `COOKIE_SECURE=true` |
| 更新后界面没变 | Docker 镜像需重建；App 界面修改后需重新构建 APK 并安装 |
| 手机显示安装包冲突 | 检查旧版签名、包名和版本号；后续更新必须用原签名密钥 |
| 23:30 后没有立即自动通过 | 正常检查间隔 30 秒；查看服务日志和打卡是否已提交，晚提交截止次日 |

## 9. 安卓后续版本和 iOS

完整源码包中 `mobile/README.md` 有详细构建步骤。这里补充实际构建记录：

**实际构建（2026-10-20）：**
- APK 大小 **3.1 MB**，签名有效至 2054-03-07
- 签名密钥位于本机 `mobile/signing/habit-garden-release.jks`，别名 `habit-garden`
- 构建环境：macOS, Java 21 (OpenJDK Homebrew), Gradle 8.14.3, Android SDK Platform 36
- **已知坑点：** macOS 启用了 WPAD 自动代理发现时，Gradle 会尝试走 `127.0.0.1:1082` 去拉 maven 依赖导致构建失败。**解决方法**是在 `mobile/android/gradle.properties` 的 `org.gradle.jvmargs` 里追加：
  ```
  -Djava.net.useSystemProxies=false -Dhttp.proxyHost= -Dhttps.proxyHost=
  ```

安卓发布密钥必须加密备份整个 `mobile/signing/` 目录，妥善保存；**不要上传到网站或公开仓库**。遗失密钥会导致无法覆盖安装，只能卸载旧版再装新版。

iOS 工程已提供（`mobile/ios/`），但需要完整 Xcode 和你自己的 Apple 签名配置才能编译、安装或分发。安卓 APK 不能直接安装到 iPhone。
